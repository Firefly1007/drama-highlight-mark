# PROGRESS 使用指南

本文件只说明怎么使用 `PROGRESS.md`，不承载项目目标、产品要求或架构决策。
要看目标形态，请先看 [README](../README.md)、[PRD](drama-interaction-v2-PRD.md)、[ADR](drama-interaction-v2-ADR.md) 和 [schema](schema.md)。

## 作用

- 作为当前状态快照的写作入口。
- 作为交接时的最短上下文。
- 作为“现在做到哪里”的单页记录。

## 什么时候写

- 完成一个可验证阶段后。
- 新增阻塞、未决项或回滚决定后。
- 做完一次有结果的测试、运行或验收后。
- 需要把当前事实交给下一位协作者时。

## 写什么

- 当前判断：一句话说明现在的整体状态。
- 当前快照：按层级列出已完成、进行中、待开始。
- 已确认的实现决策：只放已经稳定下来的选择。
- 下一步：1 到 3 条可执行动作。
- 未决项：仍然没定、但会影响后续工作的点。
- 本轮验证：命令、结果和日期。

## 不写什么

- PRD、ADR、schema 的重复正文。
- 长篇过程记录。
- 已经进入 git 历史的旧版本内容。
- 没有验证过的猜测。
- 已经过时的中间状态。

## 写法

- 只写可验证事实。
- 每条只保留一个结论。
- 用具体日期，不用“最近”“刚刚”。
- 旧内容过时就删，不要往下堆。
- 如果内容已经稳定进入 README、PRD、ADR 或 schema，就不要在这里重复。

## 建议结构

```md
## 当前判断

一句话概括当前状态。

## 当前快照

| 层级 | 状态 | 当前事实 |
| --- | --- | --- |
| ... | ... | ... |

## 已确认的实现决策

- ...

## 下一步

1. ...

## 未决项

- ...

## 本轮验证

- ...
```

## 更新顺序

1. 先写最新事实。
2. 再删过时内容。
3. 再补验证结果。
4. 最后检查 README、PRD、ADR 和 schema 的引用是否仍然一致。
