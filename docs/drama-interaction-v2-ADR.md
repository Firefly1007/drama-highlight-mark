# 短剧即时互动生成工作流 V2 — 架构决策记录（ADR）

本文只记录 V2 的当前有效架构决策。产品要求见 [PRD](drama-interaction-v2-PRD.md)，后端消费的 JSON 契约见 [schema](schema.md)。

## 当前源码架构

```text
单集原始 .mp4 + DramaContext
              ↓
 media_prepare → extract_evidence → render_evidence
              ↓
       EvidenceDocument
              ↓
 ┌──────────────────────────────────────────┐
 │ 五个 Specialist 子图并行、分支彼此隔离    │
 │ ReAct Agent ↔ inspect_span Tool           │
 │ → LangChain ToolStrategy(SpecialistResult)│
 └──────────────────┬───────────────────────┘
                ↓
          Candidate Pool
                ↓
  Deterministic Render（锚点 → 毫秒）
                ↓
 Deterministic Global Constraints
                ↓
   Semantic Scheduler（必要时） ──→ HITL
                ↓
   Final Deterministic Check
                ↓
  后端消费的 Interaction JSON
```

各 Specialist 分支均运行同一套编译子图：渲染后的分支证据视图 → ReAct Agent 按需调用分支私有的 `inspect_span` → 通过 LangChain `ToolStrategy(SpecialistResult)` 提交结构化结果 → 局部确定性校验 → 安全修复或定向重试 → Candidate Pool / HITL。

## ADR-001：删除高光作为统一中间层

**背景**：高光价值不等于互动价值；普通冲突、未揭晓问题、可接话台词和反差动作都可能产生有效互动。

**决策**：五类生成专家直接从共享证据中寻找机会，不经过统一 Highlight Detection。

**影响**：各类型可使用自己的发现标准；跨类型竞争交由下游调度处理。

## ADR-002：共享客观证据，不共享任务特定解释

**背景**：共享剧情解释会形成新的通用理解瓶颈，并将单路推理错误扩散到其他分支。

**决策**：共享层仅包含台词、屏上文本、客观视觉/音频观察和不确定性；不包含情绪、悬念、人物目标、关系变化、互动价值或模型评分。按需取证得到的派生证据只进入发起分支，不写入共享层。

**影响**：证据保持可复用和可审计；专家可以独立推理，也允许合理的上下文重复。

## ADR-003：证据按自身跨度组织，不设窗口层

**背景**：固定时间容器会复制跨界内容、制造空容器并丢失句级属性归属；稳定寻址不需要依赖网格坐标。

**决策**：落盘根契约为单个 `EvidenceDocument`：

```text
EvidenceDocument
  episode_duration_ms
  transcript_segments[]   # T<n>
  observations[]          # O<n>
```

- 所有证据条目都以自身的 `start_ms` / `end_ms` 定位；两个列表按 `start_ms` 升序，构造期校验且不自动排序。
- `episode_duration_ms` 由起始媒体预处理阶段写入工作流状态，再由证据提取节点写入文档；提取节点不自行探测或猜测媒体路径。
- 集长由真实媒体预处理提供（`ffprobe` 主视频轨时长），不从片段 JSON 的 `end` 最大值反推，也不得进入下游证据契约的其他来源。
- 预处理缺失有效集长或条目越出集长时快速失败，不静默截断。

**影响**：检索、校验、人工修正和评测都按证据标识进行；证据可直接成为锚点，未来粗粒度来源以更宽跨度表达。

## ADR-004：每条基线证据只存一份

**背景**：重复存储会放大提示词和落盘体积，也使人工修正需要同步多个副本。

**决策**：每条台词或观察只在 `EvidenceDocument` 中保存一次，不建立副本或额外引用仓库。

**影响**：一致性由结构保证，无需副本一致性校验；渲染后的时间线仍可直接供专家消费。

## ADR-005：说话人标签可匿名或为空

**背景**：上游说话人分离能力不稳定，真实角色识别不属于证据层职责。

**决策**：`speaker_label` 可为匿名标签（如 `speaker_1`）或 `null`，不要求映射真实角色名。

**影响**：保留可用的轮次信息，同时避免把身份识别耦合进证据契约。

## ADR-006：不让模型制造毫秒级事件时间

**背景**：模型可以描述内容，但自行生成的毫秒值不应被当成测量结果；观察也不必附属于台词。

**决策**：采样器或检测器提供已知边界时，记录精确跨度；模型只能得到由提取器提供的放宽跨度。`Observation` 独立于 `transcript_segments[]`，句级属性必须保留在对应条目上。

**影响**：视觉或音频事件可直接锚定到观察；跨句配乐等原生证据无需改变契约；模型侧不产生伪精确时间。

## ADR-007：本轮以 V1 适配器提供证据

> 本条关于临时生产入口的内容已由 ADR-028 取代；`EvidenceDocument` 作为上下游边界、Legacy Adapter 仅用于测试的决定仍然有效。

**背景**：重新建设 ASR、OCR 和多模态提取会阻塞下游工作流，但下游也不能直接依赖 V1 模式。

**决策**：起始媒体预处理阶段先产出 `episode_duration_ms` 并写入工作流状态；`Legacy Evidence Adapter` 接收 V1 片段 JSON 和该集长，输出 `EvidenceDocument`。当前临时实现以合法 `end` 的最大值暂代集长，未来由 FFmpeg 媒体预处理替换该来源。文本映射为 `TranscriptSegment`，音频字段映射为按原片段跨度定位的 `Observation`；适配器不处理媒体，也不猜测媒体路径。

**影响**：下游可先按稳定契约开发；未来提取器只要输出同一集长契约即可替换当前临时来源。当前适配器的可复现输入是同一 JSON 与同一集长。

## ADR-008：五类 Specialist 复用 ReAct 子图

**背景**：把机会检测、资格判断、取证和生成拆成多个独立层会重复判断同一段是否适合互动；单次模型调用又无法在需要时补充证据。

**决策**：五个固定类型的 Specialist 并行运行在同一套 LangGraph 子图骨架中。每个子图包含一个 ReAct Agent：Agent 读取本分支证据时间线，按需调用绑定当前分支的 `inspect_span` 工具，最后使用 LangChain `ToolStrategy(SpecialistResult)` 以工具调用提交 `SpecialistResult`。共用和专有提示词集中在 `src/drama_interaction/config.py`，类型文件只提供专家名称、焦点和类型专属规则，不复制执行骨架。

**影响**：每个专家可以在同一分支内完成取证和生成，天然形成扇出/扇入；结构化输出由 LangChain 约束，类型冲突不在专家内解决。

## ADR-009：专家消费文本证据，并按需取证

**背景**：业务专家不应因模型模态受限而直接访问视频、音频或帧；基线可能存在真正未处理的区间，也可能存在已经检查但没有可记录观察的区间，二者不能混为一谈。

**决策**：专家消费由 `evidence/render.py` 生成的线性文本时间线。需要补证时，子图内 Agent 通过绑定当前 Specialist 上下文的 LangChain 工具调用：

```text
inspect_span(start_ms, end_ms, query)
```

- 查询端点从时间线中已渲染的 `start_ms` / `end_ms` 复制，不由模型发明。
- `covered_empty` 不生成空的 `Observation`，在 Specialist 时间线中显示为 `[已覆盖、无可记录观察 start_ms=<起点> end_ms=<终点>]`；它不应被当作未覆盖或不确定。
- 必需提取器未处理、超时、媒体不可读或失败时，当前集直接记错并结束，不向 Specialist 发布带有 `[未覆盖]` 的半成品时间线。
- 成功单集中，固定 3 秒切片没有对应基线 `Observation` 时直接推导为 `covered_empty`，不新增覆盖表或状态模型。时间线将相邻空切片合并成一条状态行；状态行不是证据，不能被引用，也不禁止针对不同问题或更细范围的补证。
- 同一 Specialist 对同一跨度和同一问题的重复 `inspect_span` 暂由提示词提醒避免；本轮不把缓存或语义去重写入证据契约。
- 缩进观察仍带 `[O<n>]` 或 `[D<n>]` 标签；仅当其跨度不同于父条目时显示 `start_ms` / `end_ms`。Specialist 时间线不将毫秒转换为 `HH:MM:SS.mmm`。
- `inspect_span` 是无状态查询工具；工具只暴露当前 Specialist 的分支证据上下文，返回简洁的可读结果供 Agent 继续推理；派生证据由图的汇聚节点落盘。

**影响**：专家可以使用文本模型，媒体能力被封装在证据服务中；真实取证实现可独立演进。

## ADR-010：静态上下文只作辅助，当前集事实仍由证据提供

**背景**：剧名、剧情简介和角色表有助于辨认人名、关系和专有名词，但不能把简介中的跨集概括误当成本集事实。

**决策**：工作流从 `data/video/drama_info.json` 按剧名加载 `DramaContext`，将剧名、简介和角色表传给五个 Specialist 及语义调度器。该上下文只用于理解名称、关系、背景和专有名词；互动事件、动作、因果、答案与揭晓必须由当前集 `EvidenceDocument` 的 `T/O/D` 证据支撑，不额外生成跨集摘要。

**影响**：专家拥有必要的剧集语境，同时每条互动仍具备可追溯的本集证据链；简介或角色表不能单独生成互动。

## ADR-011：候选使用证据锚点，而非模型时间

**背景**：模型直接输出触发毫秒会产生无法验证的伪精确值。

**决策**：候选使用以下锚点，至少提供一个字段：

```text
trigger_anchor / reveal_anchor
  transcript_segment_id?
  observation_id?
```

- 同时提供时以 `transcript_segment_id` 解析时间。
- 标识与时间线标签逐字一致：基线使用 `T<n>` / `O<n>`，本分支派生证据使用 `D<n>`。
- 证据链字段为 `evidence_ids: list[str]`，仅可引用本分支证据视图中存在的标识。

**影响**：锚点可程序验证，并使触发位置、人工介入和评测共享同一条证据链。

## ADR-012：不用模型自评分驱动流程

**背景**：模型自报置信度、概率和分数不稳定，不能可靠地承担路由或排序职责。

**决策**：禁止将模型自评分用于类型路由、Top-K、HITL 阈值或调度排序；使用 `abstain`、证据缺失、约束失败、重试失败和冲突等可观察状态。`abstain` 表示取证后仍不足以支撑候选。

**影响**：流程由可验证状态驱动；`abstain` 率成为离线评测指标而非模型信号。

## ADR-013：局部校验先于候选池

**背景**：模式、引用和 payload 错误应在其来源分支内解决，不能污染全局候选池。

**决策**：每个专家输出后先做确定性局部校验：模式、锚点和 `evidence_ids` 是否存在于本分支视图、`refines` 是否有效且无环、payload 约束、文本长度和明显重复。不开设固定在线 LLM Critic。

**影响**：候选池只接收结构合法候选；语义质量通过专家设计和离线评测改进。

## ADR-014：失败候选定向修复与重试

**背景**：重跑整集或改变已成功候选会扩大故障范围，并浪费已有结果。

**决策**：校验失败时先做不改变业务语义的安全程序修复；仍失败则把原候选、明确错误和必要局部证据退回原专家，只修该候选；再次失败进入 HITL。LLM Gateway 使用 LangChain `ChatOpenAI`，并对配置的 `LLM_BASE_URL` 显式使用 Chat Completions API。Gateway 包裹 Specialist 子图的模型调用；网络层的超时、连接失败和限流只由 Gateway 在单次调用内重试。网关耗尽后形成可审计网络错误，直接进入 HITL，不额外消耗定向重生次数。

**影响**：修复范围可控，其他成功候选和分支不被重跑。

## ADR-015：五类专家采用部分故障隔离

**背景**：单一互动类型失败不应阻断全剧集的其余有效结果。

**决策**：五路分支独立执行并持久化成功结果；网络重试由各自调用的 LLM Gateway 处理。一条分支持续失败时只进入该分支的 HITL。每路的派生证据只在本路证据视图中可见，汇聚时按分支分组保存。

**影响**：分支错误和取证意图不会扩散，其他成功分支继续产出。

## ADR-016：HITL 通过检查点恢复

**背景**：少量候选需要人工判断，但人工处理不应导致已完成工作丢失。

**决策**：异常分支进入 `WAITING_FOR_HUMAN`，人工通过终端查看可编辑 JSON，并执行 `accept`、`edit` 或 `drop` 后从检查点恢复；HITL 是异常路径，不是全量审核。LangSmith 网页仅作为可选追踪与审计查看界面，不承担人工回写或恢复入口。

**影响**：成功证据与专家结果不重跑，最终发布在需要人工决定时暂停。

## ADR-017：同一局部时刻最多展示一个互动

**背景**：同一播放位置的多个互动会争夺用户注意力。

**决策**：候选池可保留多个类型候选，最终选择集中的展示半开区间 `[show_at, show_at + duration_ms)` 只要相交即构成冲突，最多保留一个。互动过密仍由独立的间隔、冷却和预算约束控制。

**影响**：冲突判定不依赖证据容器，规则可由基准评测校准。

## ADR-018：调度先做确定性约束，再做必要语义选择

**背景**：规则无法处理所有“两个都合法但只能留一个”的取舍，而让 LLM 重读整集又会重复专家工作。

**决策**：先程序处理重复、局部冲突、间隔、类型冷却和集预算；只有仍存在真实语义取舍时才调用调度器。调度器只读取待选候选、局部证据、已选摘要、剩余预算和硬约束，并只返回候选标识。

**影响**：调度器不是第六个完整剧情分析器；最终结果仍须通过确定性终检。

## ADR-019：互动数量使用显式预算配置

**背景**：互动密度需要可调，但没有消费者的配置只会制造伪灵活性。

**决策**：显式配置 `interaction_budget`、`min_interaction_spacing_ms` 和 `type_cooldown_ms`；调度器可以少选，不能超预算。Specialist 时间线不再使用“未覆盖区间”阈值或标记。

**影响**：数量控制集中、可基准评测调参；不保留无消费者的时间容器配置。

## ADR-020：以黄金用例隔离上游误差

**背景**：V1 时间线和内容可能有误，直接用其结果难以判断是上游证据还是下游工作流出错。

**决策**：准备少量人工校正的证据时间线和代表性互动机会作为 golden fixtures；后半链路优先在 fixture 上开发和评测，真实 V1 适配结果仅做端到端冒烟验证。

**影响**：下游能力可独立评估，未来替换提取器时仍能复用同一评测基线；fixture 重建需要对应视频以探测集长。

## ADR-021：质量采用离线基准评测

**背景**：在线 Judge 会增加生产链路成本和不确定性，不适合作为必经环节。

**决策**：离线评测覆盖互动发现、触发正确性、内容质量/实据/剧透、调度质量、鲁棒性，以及调用次数、重试、HITL 和耗时。按需取证额外记录每路调用次数、非空命中率和派生证据被候选引用的比例。LLM-as-a-Judge 仅可作为离线辅助。

**影响**：质量改进有可比较依据；取证数据可为未来上限或缓存决策提供证据。

## ADR-022：工作流框架使用 LangGraph

**背景**：五路并行、局部修复、故障隔离、人工等待和检查点恢复需要统一的状态编排。

**决策**：V2 后半链路使用 LangGraph `StateGraph`。`EvidenceDocument` 是共享数据契约，工作流状态承载单集元数据和节点进度；五个 Specialist 使用可编译、可嵌入父图的 LangGraph 子图；一个 `execution_id` 只处理一集，不接收或聚合跨集范围。PostgreSQL 是检查点介质，连接只从 `CHECKPOINT_DATABASE_URL` 读取，`execution_id` 同时作为 LangGraph `thread_id`。入口层负责参数校验，图内节点保持单一职责；LangSmith 追踪可选启用且只读。

**影响**：复用框架的持久化和恢复能力，不自建检查点；单集失败或中断不会污染其他集。

## ADR-023：锚点到最终 JSON 的确定性渲染

**背景**：候选只有证据锚点，后端最终 JSON 需要绝对毫秒字段与稳定 payload；V1 的时间推导和无种子选项打乱均不可复现。

**决策**：候选池之后、全局约束之前执行 `render_node`；其中 `resolve_anchor` 是 `scheduling/constraints.py` 的唯一共用实现，并从候选所属分支证据视图中取得被引用条目的跨度：

```text
show_at      = trigger_anchor 对应条目的 start_ms
duration_ms  = repeat_keyline 时按锚区间 + keyline_tail_ms 并限幅；其余类型取 type_base
reveal_time  = deferred_vote 的 reveal_anchor 对应条目的 start_ms
reveal_delay = reveal_display_ms
```

- 生成专家不输出任何毫秒字段；如有结构性违规，可安全置空后由渲染重算。
- `deferred_vote` 必须满足 `reveal_time >= show_at + duration_ms + reveal_gap_min_ms`，不满足时丢弃并记录原因，不进入定向修复。
- 投票选项使用固定项目命名空间的 `UUIDv5(execution_id:candidate_id)` 作为局部随机种子确定性打乱，并同步重映射 `answer_id`；不使用 Python 内置 `hash()` 或全局随机状态。
- 最终输出的 `type` 仅为字符串：`emotion_button`、`repeat_keyline`、`instant_vote`、`deferred_vote`、`side_comment`；不公开数字映射。
- `side_comment.payload.mood` 为必填小写枚举：`roast`、`shock`、`laugh`、`praise`、`sympathy`、`doubt`；`emotion_button.payload.button_id` 直接使用 `cool`、`laugh`、`tomato`、`protect`、`pity`、`ship`。
- 最终数组按 `(show_at, duration_ms)` 排序，`id` 为从 1 开始的连续序号。

**影响**：时间校验、冲突处理、调度和导出消费同一份真实毫秒；后端类型契约稳定，选项顺序可复现。

## ADR-024：按需取证证据可锚定且分支私有

**背景**：补充证据必须能被候选引用，同时不能破坏基线幂等、共享证据客观性和五路隔离。

**决策**：`inspect_span` 工具返回的补充证据使用独立的 `DerivedObservation`：

```text
DerivedObservation
  id: D<n>                 # 分支内序号
  start_ms / end_ms
  visual_observations[] / onscreen_texts[] / audio_observations[] / uncertainty[]
  refines: O<n> | D<n> | null
  provenance:
    specialist
    query_span: { start_ms, end_ms }
    query
```

- 分支证据视图等于基线加本分支派生证据；`D<n>` 可用于锚点和 `evidence_ids`，但对其他分支不可见。
- 基线文件永不写回；汇聚节点将所有派生证据（包括未被引用的）按分支落至 `data/interaction_v2/runs/<execution_id>/evidence-derived.json`。
- `refines` 只能指向本分支视图中的基线观察或派生观察，且不能成环。
- 取证调用记录 Specialist、跨度、查询、返回条数、可用性和失败原因；取证失败不阻断分支。

**影响**：补证针对 Specialist 明确查询的时间范围；基线提取错误不会伪装成可继续消费的未覆盖区间。基线保持确定性，派生过程保留审计和评测价值。

## ADR-025：ASR 句段时间戳直接形成台词证据

**背景**：托管 ASR 可以直接返回带起止时间的台词句段；V2 只需让每条台词证据在媒体时间轴上可定位，不需要逐词展示或逐词锚定。

**决策**：

- ASR 提取器将 provider 返回的句段 `text/start/end` 直接映射为 `TranscriptSegment.text/start_ms/end_ms`；可用的匿名说话人标签映射到 `speaker_label`。
- 不向 `TranscriptSegment` 增加 `words[]`，不要求保存或消费 provider 的逐词时间戳，也不进行二次组句。
- 所有句段时间都须通过媒体范围、正序和跨度校验；不由 LLM 生成或修正时间边界。
- 短剧单集必须产生至少一个合法 `TranscriptSegment`；即使 ASR 请求成功，返回零句段也视为提取异常。
- 缺少必要时间戳或校验失败时当前集记错并结束；批量运行继续下一集。OCR/VLM 观察继续使用采样器提供的媒体切片边界。

**影响**：现有 `TranscriptSegment` 契约已经足够，台词时间来源单一且可校验；不引入未被 Specialist 或锚点消费的逐词结构。

## ADR-026：视觉基线使用固定非重叠媒体切片

**背景**：OCR/VLM 不提供可直接信任的事件时间；整集视觉观察需要可复现的时间边界，又不应重新引入 V1 的高光筛选或让模型自报毫秒。

**决策**：视觉基线先按固定、非重叠的 3 秒媒体时间范围切片，最后不足 3 秒的尾段单独保留。采样器/FFmpeg 拥有切片边界，OCR/VLM 只返回该范围内的客观文本观察；切片长度使用 `3000ms`。不先引入镜头检测、逐帧扫描或事件驱动切片。

**影响**：视觉处理范围和采样位置可复现，观察可以直接继承切片跨度；后续若评测证明固定切片不足，可替换采样策略而不改变 Specialist 的证据契约。

## ADR-027：覆盖状态与证据内容分离

**背景**：先前将“无法可靠观察”的区间统一标记为未覆盖或不确定，会把已成功检查但没有可记录事实的空切片误报为提取失败，也会让 Specialist 无法区分“没有观察”与“没有检查”。

**决策**：只有所有必需提取器完成的单集才能发布基线证据，因此覆盖状态可由固定切片网格直接推导，不写入 `EvidenceDocument` 也不新增覆盖表：

- `covered_empty`：固定 3 秒切片没有对应基线 `Observation`，表示三路提取均按既定采样策略成功处理但没有返回可记录的客观观察；不生成空证据，不自动填写 `uncertainty`。它不表示逐帧检查过该范围，也不表示其中没有发生事件。
- `uncertain`：提取器确实返回了观察，但明确指出观察内容无法可靠判定；只有此时才填充观察条目的 `uncertainty`。
- 提取器未处理、媒体不可读或失败：记录单集提取错误并结束当前集，不创建或发布带有“未覆盖”标记的 Specialist 时间线。

`covered_empty` 显示为 `[已覆盖、无可记录观察 start_ms=<起点> end_ms=<终点>]`，相邻空切片先合并；它不是证据。Specialist 输入中不存在 `[未覆盖]` 状态行。提取错误和具体观察不确定性分别由单集错误记录与观察条目的 `uncertainty` 表达。这条决策取代此前“任何无法可靠观察区间都必须标记为未覆盖或不确定”的笼统规则。

**影响**：空结果不会伪装成事实，也不会把正常的无内容区间升级为错误；固定切片网格已足以表达覆盖，不增加重复状态数据。

## ADR-028：生产证据入口使用原始视频

**背景**：当前代码的入口仍接受 V1 片段 JSON，并用文本条目的最大结束时间临时推断集长；这无法形成“原始视频 → 完整基线证据”的 V2 生产链，也会把 V1 的错误带入证据层。

**决策**：

- 生产 `run` 接受单个原始 `.mp4` 或视频目录；视频文件是单集的权威输入。目录输入递归发现其下所有 `.mp4`，因此既可传入单剧目录，也可传入 `data/video` 一次处理多部剧。
- 批次按视频相对输入根目录的路径做确定性自然排序，其中数字片段按数值比较，使 `第2集` 排在 `第10集` 之前；然后逐集串行处理。
- 按 `data/video/<剧名>/<集名>.mp4` 约定解析剧名与集名，并加载对应 `DramaContext`；`episode_duration_ms` 只取 `ffprobe` 探测到的主视频轨时长。腾讯云数据万象 CI 的 `dialogue` 和 `background` 输出分别保留为本地 `dialogue.mp3`、`background.mp3`；`dialogue` 的临时签名 URL 提供给 ASR，`background.mp3` 再按该集长硬切供三秒音频观察使用；不增加多轨容差协商或时长回退。没有可用主视频轨及其时长时当前集失败。
- `data/text` 和 V1 片段 JSON 只用于 golden fixture、回归测试或兼容适配验证，不参与生产证据生成，也不用于推断集长。
- 视频不可读、时长探测失败或生产提取阶段发生必需错误时，当前集记为失败并结束；批量运行继续下一集。

**影响**：V2 的证据来源边界清晰，后续 ASR/OCR/VLM 都从同一份真实媒体和真实集长出发；V1 适配器保留为测试工具，不再是生产上游。

## ADR-029：OCR 与 VLM 独立分工，在证据层合并

**背景**：OCR 与 VLM 都能尝试读取画面文字，但让 VLM 同时承担精确文字识别和视觉语义描述会增加任务负担；只保留其中一个又会牺牲另一类事实的召回或精度。

**决策**：

- OCR 只负责屏幕文字，结果写入 `Observation.onscreen_texts`。硬字幕与其他屏幕文字一并保留；除丢弃空字符串外，不做字幕分类、语义纠错或与 ASR 去重。屏幕字幕不转换为 `TranscriptSegment`，台词及其时间仍以 ASR 输出为准。
- VLM 只负责动作、人物关系、画面状态和视觉反差等客观视觉观察，结果写入 `Observation.visual_observations`；不要求它重复 OCR。
- 两个提取器对同一视觉采样切片独立执行；程序按同一切片跨度把非空结果确定性合并为一个 `O<n>`。
- OCR、VLM 或音频观察中任一路为空但其他路有结果时仍生成观察；三个必需提取器均成功且结果全为空时记录 `covered_empty`。
- 是否以后用单一 VLM 或条件路由替代双路，留给样本评测决定，不在当前 MVP 中预设。

**影响**：每种模型的提示词和失败边界更小，Specialist 获得统一的切片观察；合并发生在数据层，不会把 OCR 文本额外塞进 VLM 任务。

## ADR-030：视觉提取使用确定性采样帧

**背景**：不同 VLM 对视频输入的支持和时序行为不一致；直接把原始视频片段交给模型会增加供应商耦合和不可复现性，而 OCR 本身也需要图像帧输入。

**决策**：固定的 3 秒视觉切片仍由真实媒体时间边界定义。暂定使用 `4 FPS`：每个切片按 250 毫秒分桶并取桶中间帧，完整切片相对起点的帧位置为 `125ms`、`375ms`、……、`2875ms`；最后不足 250 毫秒的尾桶取其自身中点帧。一个完整切片最多 12 帧，按采样顺序作为 OpenAI 兼容的 `image_url` 内容块分别交给 OCR 和 VLM；4 FPS 由本地帧序列体现，不再向不兼容的视频内容块传 `fps` 字段。两种模型共享同一帧集合和切片边界，每个模型每个切片只调用一次，也不让模型自行决定时间范围。VLM 请求除通用观察指令外只接收该序列，不接收 `DramaContext`、台词、OCR 或音频结果；无法从画面证据确认角色时使用中性外观描述，不猜测姓名。多帧只能支持可见状态和变化；没有被任一采样帧显示的中间过程，不补写为已发生的具体动作。

`4 FPS` 是尚未验证的 MVP 基线，不代表视觉内容无遗漏。等项目存在可复用的视觉 benchmark 后，再以同一模型和提示词比较 `2/4/8 FPS`，选择能够保留关键视觉事实的最低采样率；此前不增加镜头检测、自适应采样或第二套视频输入路径。

**影响**：视觉提取可在不同模型供应商之间复现和替换；每个完整切片最多产生 12 张输入帧和每个模型一次调用，源视频提前结束时只保留真正取到的帧而不补帧。相比原暂定的 `1 FPS`，调用次数不变，单次视觉输入量增至四倍；采样仍可能漏掉短于 250 毫秒的瞬时画面以及跨切片动作。

## ADR-031：上游模型使用托管 API，背景音频按既有观察跨度合并

**背景**：V2 需要从原始视频补齐 ASR、OCR、视觉和非台词音频观察，但本项目不承担模型部署；同时，直接让音频模型处理台词与背景声混合的音轨会增加非台词声音被忽略的概率。

**决策**：

- ASR、OCR、VLM、音轨分离和音频观察模型均通过托管 API 调用；本地只使用 FFmpeg/FFprobe 完成媒体探测、抽取、采样和硬切，不运行推理模型。
- 音轨分离服务先对整集媒体产生时间对齐的台词音轨与背景音轨；台词音轨是 ASR 的唯一输入，背景音轨保留音乐与音效，是基线音频观察的唯一输入。ASR 和音频观察都不再读取原始混合音轨。
- 背景音轨沿用 ADR-026 的固定 3 秒非重叠跨度切片，音频模型只描述该跨度内可听见的客观事实，不自行生成时间。
- 音频观察请求的唯一媒体输入是当前 3 秒背景音频切片；不附带采样帧、台词或 OCR 结果。视觉、OCR 与音频三路独立提取，只在程序层按跨度合并。
- 音频模型可记录声源、声音事件和可听见的变化，例如脚步、撞击、急促鼓点或音乐骤停；不得写声音营造的情绪、对剧情的暗示、角色心理或互动价值。
- 当前切片无可辨识的音乐、音效或环境声时，`audio_observations` 返回空数组，不生成“安静”之类的占位描述；切片内明确可听的转入或退出静音仍作为声音变化记录。
- 每个背景音频切片独立描述当前可听事实；持续声音跨越多个切片时允许重复记录，不增加跨切片语义去重。
- OCR、VLM 和音频观察的非空结果按同一跨度确定性合并进既有 `Observation`，分别写入 `onscreen_texts`、`visual_observations` 和 `audio_observations`；不新增 `A<n>` 或其他音频证据类型。
- 环境变量按能力使用 `AUDIO_SEPARATOR_*`、`ASR_*`、`AUDIO_OBSERVER_*`、`OCR_*` 和 `VLM_*` 前缀；人声分离使用 `AUDIO_SEPARATOR_ACCESS_KEY_ID`、`AUDIO_SEPARATOR_ACCESS_KEY_SECRET`、`AUDIO_SEPARATOR_BUCKET`、`AUDIO_SEPARATOR_REGION`，变量名不包含供应商或具体模型名称。
- MVP 为每项提取能力只实现当前选定的一种 API 协议；通用配置名只解除名称耦合，不承诺通过配置切换任意供应商，因此不增加 `*_PROVIDER`、插件注册或尚无第二实现的适配层。
- COS/CI 官方 SDK 与 OpenAI-compatible Qwen 调用沿用有限重试口径：超时、连接失败、限流和服务端错误最多重试 3 次；鉴权失败、请求参数错误和响应结构非法不重试。DashScope ASR 使用官方 SDK 自带的有限网络重试，外层不叠加公共重试；SDK 重试耗尽、子任务失败或结果结构非法时当前集失败。
- 批次中的单集串行处理；单集内的 3 秒切片也串行处理，但当前切片的 OCR、VLM 和音频观察三路 API 调用并发，三路都完成后才进入下一切片。不增加跨切片并发或相关配置。

**影响**：项目无需本地 GPU 或模型运维，供应商信息被限制在配置值和调用适配代码中；音轨分离成为 ASR 与音频观察共同的必需前置阶段，两个输出任一不可用都不能形成完整基线证据。代价是依赖外部服务的可用性、费用和媒体上传。背景分离可能遗漏被归入台词音轨的非语言人声，这属于当前基线接受的精度边界。
