# 短剧即时互动生成工作流 V2 — 产品需求文档（PRD）

本文定义 V2 交付什么、何时算合格。架构取舍见 [ADR](drama-interaction-v2-ADR.md)，最终 JSON 字段以 [输出契约](schema.md) 为准。

## 1. 产品定位

V2 是面向单集短剧的离线互动点生成引擎。它从本集**完整原始视频**建立证据，再输出一组适时、可参与且不打断观看的即时互动配置。

产品不以“高光”作为前置筛选层。普通冲突、关键台词、未揭晓问题、视觉反差和声音事件都可以成为互动机会；是否保留由证据、互动类型规则和全局调度共同决定。

## 2. 输入、输出与范围

### 输入

- 一集 `.mp4` 原始视频。
- 按剧名匹配的剧情简介与角色表，作为名称、关系和专有名词的辅助上下文。

### 输出

- 一份完整的整集基线证据：台词、屏幕文字、客观视觉观察和背景音观察均按整数毫秒定位。
- 零到多条最终互动 JSON；每条均包含展示位置、展示时长、固定字符串 `type` 和对应载荷。

### 包含

- 固定支持 `emotion_button`、`repeat_keyline`、`instant_vote`、`deferred_vote`、`side_comment` 五类互动。
- 整集层面的候选去重、冲突处理、间隔/冷却/预算控制与必要的人工决定。
- 中断后从同一执行恢复，避免重复已完成的工作。
- 单集失败记录、目录批处理继续下一集。

### 不包含

- 前端播放器、业务服务、业务数据库、账号体系和评论区。
- 剧情分支、跨集记忆、跨集摘要、AIGC 分支内容或其他互动形态。
- `episode_comment`、`scene_bookmark`、`heatmap_bar`。
- 本地部署 ASR、OCR、VLM、音轨分离或音频观察模型。

## 3. 证据要求

1. 当前集的事件、人物动作、因果、答案、台词和揭晓必须能追溯到本集证据；剧情简介和角色表不能单独触发互动。
2. ASR 句段的起止时间直接作为台词证据时间，不由模型或程序二次切句、补偿或臆造。
3. 视觉和背景音观察使用固定 3 秒范围；OCR、VLM 和背景音观察的非空内容合并为同一条观察。
4. 成功处理但三路观察均为空的切片，可在 Specialist 时间线中显示为“已覆盖、无可记录观察”；这不是可引用事实，也不表示视频中没有发生任何事。
5. 必需提取器失败、超时或媒体损坏时，该集不得向 Specialist 交付半成品证据。

## 4. 五类互动

| 类型 | 产品行为 | 使用条件 |
| --- | --- | --- |
| `emotion_button` | 展示可点击的情绪按钮，可附短文案或预设弹幕。 | 证据直接支持爽、笑、吐槽、保护、心疼或甜宠等即时情绪。 |
| `repeat_keyline` | 邀请用户复述或接住一句关键台词。 | 文案是本集实际台词的连续片段，且本身具有名场面、态度或节奏感。 |
| `instant_vote` | 展示二选一投票。 | 存在两个互斥、可理解且都值得用户选择的当下判断。 |
| `deferred_vote` | 先对悬念/预测投票，后随剧情揭晓。 | 本集后续存在明确、可追溯的揭晓；题干不能提前泄露答案。 |
| `side_comment` | 展示一句短吐槽、短评或提醒。 | 当前节点有明确反差、情绪或讨论价值，且评论不剧透。 |

共同规则：不编造剧情、台词、人物关系、答案或揭晓；证据不足时宁可不生成。`instant_vote` 恰有两个选项；`deferred_vote` 有二至四个互斥选项，并在展示结束后才可揭晓。

## 5. 展示与调度规则

- 每项互动应在用户已经理解相关内容后展示；候选的展示位置由引用证据的开始时间确定。
- 任意两个最终互动的展示区间不得重叠。
- 同类冷却、最小间隔和单集互动预算由全局调度统一处理；系统可以少选，不能为了凑数量强行生成。
- `deferred_vote` 的揭晓必须晚于投票展示结束，并与投票内容相符。
- 最终结果按展示时间排序，并能由后端直接解析，不需要后端重做生成、时间推导或冲突判断。

## 6. 人工处理与失败行为

- 专家候选、语义取舍或最终约束无法自动解决时，执行进入人工门控；人工可接受、编辑或丢弃，再从同一执行恢复。
- 上游媒体/证据提取阶段的必需错误属于当前集失败，不进入半成品生成流程。
- 目录运行中，一集失败不阻断后续集；已完成集的结果保持可用。

## 7. 验收标准

1. 对一集可读原始视频，系统能得到至少一条带有效毫秒时间的台词证据，并保存完整 `EvidenceDocument`。
2. 证据建立后，五类 Specialist 可独立弃权或输出候选；最终只会出现五个规定的字符串 `type`。
3. 每个最终互动都有本集可追溯证据，不能借简介或角色表单独补造当前集事实。
4. 最终 JSON 的时间、载荷、投票选项、揭晓关系、排序和展示区间均满足 [输出契约](schema.md) 与全局约束。
5. 成功的三路空观察与提取失败可被区分：前者只生成非事实状态行，后者使当前集失败。
6. 中断或人工门控后可按同一执行恢复；目录任务在单集失败后继续。
