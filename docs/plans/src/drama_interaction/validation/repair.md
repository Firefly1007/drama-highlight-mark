# validation/repair.py 内容计划

本模块处理候选级失败：安全程序修复、定向重生和人工介入交接。

## 职责与边界

- 只处理一条失败候选，按安全修复、原专家定向重生、人工交接的顺序推进。
- 保存每次尝试的输入、输出和错误历史。
- 不重新扫描整集、不重新运行专家全量生成、不修改其他成功候选或基线证据。

## 输入、输出与接口

- 输入为失败 Candidate、rules 输出的错误、当前分支局部证据和专家标识。
- 输出为修复后的候选、需要再校验的结果，或包含上下文的 HITL 事件。
- 定向重生调用 specialists/base 的单条接口，而非再次调用整集专家。

## 依赖与消费者

- 依赖 validation/rules、specialists/base、schemas/candidate、evidence/render 和 llm。
- graph/nodes 负责校验—修复循环和暂停；CLI 展示最终 HITL 事件。

## 目标实现要求

- 安全修复只允许不改变业务语义的规范化，例如清理空白、可证明的格式规范和删除生成侧非法毫秒。
- 每次程序修复后必须重新运行全部局部规则。
- 非安全错误构造原候选、结构化错误和局部证据，定向退回同一专家生成一条替代候选。
- 重生仍失败时生成 HITL 事件，带完整错误历史和尝试记录。

## 失败与边界情形

- 不得改写题干、选项、金句文本、锚点、证据引用或 answer_id 来伪装修复成功。
- 不能安全修复的候选不能被静默丢弃；必须定向重生或交给人工。
- 重试上限、白名单扩展和 HITL 字段细节只维护在 [PROGRESS](../../../../PROGRESS.md)。

## 验证

- 覆盖安全修复成功、白名单外操作被拒绝、定向重生成功和重生耗尽。
- 断言定向重生只接收局部证据和一条候选。
- 验证每次尝试都留下可读的修复记录。
- 验证任何接口都不能传入整集重扫或其他候选。
