# specialists/base.py 内容计划

本模块提供五类生成专家（Specialist）的公共执行骨架。

## 职责与边界

- 组装专家输入、提示词要素、模型调用、JSON 解析、弃权结果和单条定向重生入口。
- 负责把本分支证据时间线与 inspect_span 工具交给专家。
- 不实现类型专属的内容判断，不渲染证据，不做确定性校验、调度或图编排。

## 输入、输出与接口

- 输入包含 specialist_type、静态上下文、本分支 EvidenceDocument 视图、evidence_timeline、模型客户端和取证工具。
- 正常输出为 SpecialistResult；单条重生输入为原 Candidate、结构化错误和局部证据，输出只是一条替代候选。
- 提示词要求输出候选、锚点、evidence_ids 和弃权，不要求或接受绝对毫秒、候选 id、评分或置信度。

## 依赖与消费者

- 依赖 schemas/candidate、schemas/evidence、evidence/render、evidence/service、llm 和 config。
- 五个类型专家复用本模块；graph/nodes 负责调用；validation/repair 调用单条重生接口。

## 目标实现要求

- 提示词中明确：当前集事实只能由当前集证据支撑，静态上下文只用于专名和身份理解。
- 锚点只能复制时间线可见的 T<n>、O<n>、D<n>；不得自行发明毫秒或引用其他分支的 D<n>。
- inspect_span 的返回只扩展当前专家分支，重新渲染后才可被该分支候选引用。
- 解析失败保存原始模型返回和原因，交给校验、修复或人工流程；不得悄悄重跑整集。
- 弃权表示在允许取证后仍缺乏安全依据，不是低置信度的数值替代。

## 失败与边界情形

- 模型返回不是合法 JSON 或不符合 SpecialistResult 时形成结构化失败。
- 取证不可用或失败时保留审计并继续使用已有证据，不补造事实。
- 单条重生只能接收该候选及其局部上下文，不得重扫整集或触碰其他候选。
- 提示词措辞、单条重试次数等未冻结细节只维护在 [PROGRESS](../../../../PROGRESS.md)。

## 验证

- 使用假模型覆盖合法候选、仅弃权、围栏 JSON 和非法 JSON。
- 断言 evidence_timeline 原样进入提示词，且只注入当前分支的取证接口。
- 断言单条重生只返回一条候选并只使用局部证据。
- 断言失败记录保留原始返回且不会触发整集重跑。
