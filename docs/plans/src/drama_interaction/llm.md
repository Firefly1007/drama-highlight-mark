# llm.py 内容计划

本模块封装大语言模型（LLM）的唯一网络出口。

## 职责与边界

- 统一装配 OpenAI 兼容客户端、执行文本调用、解析结构化 JSON、处理瞬时网络失败并记录审计信息。
- 服务于生成专家、语义调度器和定向重生。
- 不保存业务提示词，不判断剧情，不做候选语义修复，也不决定工作流级重试。

## 输入、输出与接口

- 调用入口接收 system 文本、user 文本、调用标签和模型参数。
- 原始调用输出为文本；结构化调用返回解析后的对象或携带原始响应的解析错误。
- 每次调用产生包含调用标签、模型、耗时、成败和可得用量的审计记录。

## 依赖与消费者

- 依赖 config 提供模型标识、密钥、端点和超时设置。
- specialists/base、scheduling/semantic、validation/repair 是唯一业务消费者。

## 目标实现要求

- 进程内复用客户端，调用方不得自行创建网络客户端。
- 对超时、连接错误和限流进行有限短重试；耗尽后抛出可分类异常给图层处理。
- JSON 解析只做语法层恢复，例如去除 Markdown 围栏；不得猜测字段、补全内容或改变语义。
- 调用标签为必填，确保成本、失败和时延可按专家、调度或修复归因。

## 失败与边界情形

- 配置缺失、网络错误、超时、限流和解析失败均保留足够上下文供上层记录。
- 解析失败必须包含原始返回与失败原因，不能静默返回空对象。
- 单次模型调用失败不直接意味着整集失败；图层决定分支重试、人工介入或继续。
- SDK、采样参数和用量字段等未冻结内容只维护在 [PROGRESS](../../../PROGRESS.md)。

## 验证

- 使用假客户端覆盖正常 JSON、围栏 JSON、非法 JSON、瞬时失败和重试耗尽。
- 断言解析不会修改有效业务字段。
- 断言审计记录包含标签、耗时和结果。
- 断言所有业务模块通过本模块调用模型。
