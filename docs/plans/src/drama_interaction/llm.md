# llm.py 内容计划

本模块封装大语言模型（LLM）的唯一网络出口。

## 职责与边界

- 统一装配 LangChain ChatOpenAI，通过通用 `LLM_BASE_URL` 显式使用 Chat Completions API，调用已编译的 Agent、处理瞬时网络失败并记录审计信息。
- 服务于生成专家、语义调度器和定向重生。
- 不保存业务提示词，不判断剧情，不做候选语义修复，也不决定工作流级重试。

## 输入、输出与接口

- 调用入口接收已编译 Agent、Agent 状态输入和调用标签。
- 调用返回 Agent 状态；结构化结果只由调用方从 LangChain `ToolStrategy` 写入的 `structured_response` 读取。
- 每次调用产生包含调用标签、模型、耗时、成败和可得用量的审计记录。

## 依赖与消费者

- 依赖 config 提供模型标识、密钥、端点、超时和最大输出 token 设置。
- specialists/base、scheduling/semantic、validation/repair 是唯一业务消费者。

## 目标实现要求

- 进程内复用 ChatOpenAI，调用方不得自行创建模型客户端。
- 当前 timeout 和 max_tokens 先使用较大配置值传给 ChatOpenAI，正式限制待 benchmark 决定。
- 对超时、连接错误和限流进行有限短重试；网络重试只在本模块执行，耗尽后抛出可分类异常给图层处理。
- 不解析模型文本 JSON，不提供旧 JSON 调用接口或回退路径。
- 调用标签为必填，确保成本、失败和时延可按专家、调度或修复归因。

## 失败与边界情形

- 配置缺失、网络错误、超时和限流均保留足够上下文供上层记录。
- Agent 未形成合法结构化结果由调用方记录原始状态并进入该分支的校验或人工流程。
- 单次模型调用失败不直接意味着整集失败；网络重试耗尽时图层记录该分支的可审计错误并进入 HITL，不再把同一次网络故障计为额外业务重生。
- LangChain 模型、采样参数和用量字段由网关配置统一承载；运行状态见 [PROGRESS](../../../PROGRESS.md)。

## 验证

- 使用假 Agent 覆盖正常状态、瞬时失败和重试耗尽。
- 断言网关不会引入文本 JSON 解析或结构化回退。
- 断言审计记录包含标签、耗时和结果。
- 断言所有业务模块通过本模块调用模型。
