# src/drama_interaction/llm.py 内容规划

- 状态：规划中（未实现）
- 上游依据：ADR-009、ADR-018、PRD §20.2（可观测性）、README.md 结构树

## 职责与边界

- 全项目唯一的 大语言模型(LLM)网络出口封装：任何模块不得自行创建模型客户端。
- 提供三类调用方共用的基础能力：客户端装配、带超时的文本补全调用、JSON 结构化输出的解析与容错、调用审计。
- 明确不做：不包含任何业务 提示词(Prompt)（提示词(Prompt)属各 生成专家(Specialist)与 调度器(Scheduler)模块）；不做节点级故障隔离（那是 LangGraph 重试策略(RetryPolicy)与分支语义的事）；不做内容理解决策。

## 依赖关系

- 依赖 config.py（LLM_MODEL_ID / LLM_API_KEY / LLM_BASE_URL 三要素与超时等默认参数）。
- 被三个模块依赖：specialists/base.py（五类 生成专家(Specialist)调用）、scheduling/semantic.py（调度器(Scheduler)调用）、validation/repair.py（定向退回重生成调用）。
- 与 LangGraph 的分工：调用层只处理单次请求的瞬时失败（超时、连接错误、限流的短重试）；节点级重试上限、分支隔离、成功结果持久化由 图(graph)层负责（ADR-015）。

## 主要组成

- 客户端装配：按 config 三要素构建 OpenAI 兼容 client，进程内复用单例；模型 标识(ID)、base_url 不散落在调用方。
- 补全调用封装：统一入口接收 system/user 文本与调用标签（用于审计），返回原始文本；内置请求超时与瞬时错误（网络、限流）的有限次短重试，重试次数与退避为可配置常量。
- JSON 解析容错：对模型返回做分层解析——先直接解析，失败则剥离 markdown 围栏等包裹物再解析，仍失败则抛出携带「原始返回全文 + 解析失败原因」的结构化错误，交由上层（base / semantic / 修复(repair)）按各自语义处理，本层不做语义补救。
- 调用审计：每次调用记录标签、模型、耗时、成功/失败、词元(token)用量（如接口(API)可得），汇总供 PRD §20.2 的可观测性要求（调用次数、耗时）与 基准评测(benchmark)统计。

## 关键设计点

- 生成专家(Specialist)可全部使用纯文本模型（ADR-009）：本层只要求 OpenAI 兼容的文本补全接口，不绑定多模态能力。
- 解析容错只做「语法层」恢复（剥包裹、修编码），绝不做「语义层」补救（不猜字段、不改内容）——语义错误必须走 校验(Validation) / 修复(Repair)通道（ADR-013/014）。
- 调用标签强制要求：每个调用点必须声明身份（哪个 生成专家(Specialist) / 调度器(Scheduler) / 修复(Repair)），保证计数可归因。
- 单次调用失败不等于分支失败：本层短重试耗尽后抛出的是可分类异常，由节点层决定进入 重试策略(RetryPolicy)还是分支级处理。

## 待定项

- 开发工具包(SDK)选型：OpenAI 官方 开发工具包(SDK)还是轻量 HTTP 封装（倾向官方 开发工具包(SDK)，兼容第三方 base_url）。
- 温度等采样参数的默认值与是否可按调用点覆盖。
- 词元(token)用量统计依赖各兼容端点返回格式，字段可得性待实测。

## 测试要点

- 注入假 client：三种解析情形（纯净 JSON、围栏包裹、完全非法）的行为可完全离线测试。
- 瞬时错误重试的触发与耗尽路径可模拟测试。
- 审计记录的完整性（标签、耗时、成败）可断言。
