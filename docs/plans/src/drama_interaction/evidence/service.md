# evidence/service.py 内容计划

本模块定义按需取证（On-Demand Evidence）服务的统一接口与调用审计。

## 职责与边界

- 接收专家对一个时间跨度的具体问题，返回该分支可用的 DerivedObservation 或明确不可用结果。
- 记录取证请求与结果，保持取证内容仅以文本形式暴露给专家。
- 不改写基线 EvidenceDocument，不把一个分支的派生证据共享给其他分支，也不负责汇聚文件落盘。

## 输入、输出与接口

- inspect_span 接收 start_ms、end_ms、query 以及调用 Specialist 上下文。
- 合法结果包含派生观察列表、可用性和失败原因；每个派生项带 refines 与 provenance。
- 审计记录至少包含 Specialist、跨度、查询原文、返回条数、可用性和失败原因。

## 依赖与消费者

- 依赖 schemas/evidence 和适配器提供的基线证据；真实服务实现可依赖上游媒体或提取能力。
- specialists/base 注入并调用该接口；graph/nodes 在汇聚时写出按分支分组的派生证据记录。

## 目标实现要求

- 校验跨度位于本集范围内、start_ms 不晚于 end_ms、query 非空且具体。
- 返回的 D<n> 只追加到发起分支视图；编号在该分支内稳定，不能因为汇聚而重写。
- 未来媒体能力的替换只能改变服务内部，不能改变 inspect_span 调用方或返回结构。
- 服务不可用、超时或无结果时不能虚构证据；专家可使用已有证据继续或弃权。

## 失败与边界情形

- 无效跨度和空泛问题返回结构化输入错误。
- 真实取证失败要记入审计，不能让其他专家分支失败或污染基线文件。
- 派生观察引用不存在、跨分支或成环必须在构造期拒绝。
- 调用上限、缓存和真实提取实现的未冻结政策只维护在 [PROGRESS](../../../../PROGRESS.md)。

## 验证

- 覆盖合法、无效和越界调用，以及明确不可用结果。
- 验证失败时不产生虚构观察、不修改基线且其他分支仍可继续。
- 验证审计字段完整，D<n> 的编号和 Specialist 隔离正确。
- 验证 graph 汇聚前服务不写运行目录或最终产物。
